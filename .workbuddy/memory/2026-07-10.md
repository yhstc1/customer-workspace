## Zeabur 部署适配
需求：把项目部署到 Zeabur。
- **核心坑**：本地 `python app.py` 靠 `__main__` 调 init_db()，但 gunicorn 不走 __main__ → 表建不出来 → 线上首请求 500。解决：把 `init_db()` 提到 app.py 模块级（app.secret_key 之后），幂等，try/except 包裹。
- requirements.txt 加 `gunicorn>=21.2.0`。
- models.py 在 DB_PATH 定义后加 `os.makedirs(dirname(DB_PATH), exist_ok=True)`（云端容器无 data/ 目录会导致 sqlite 连接失败）。
- 新建 `zbpack.json`：`{"start_command":"gunicorn app:app -b 0.0.0.0:$PORT --workers 2 --timeout 120"}`。
- 新建 `.gitignore`（忽略 *.db / __pycache__ / reports/*.html），data/ 与 reports/ 加 .gitkeep 保留空目录。
- git init + 两次提交完成，待用户 `git remote add` + push。
- **持久化警告**：Zeabur 容器磁盘临时，必须挂 Volume 到 `/src/data`，否则 SQLite 数据重部署即丢。
- 环境变量：FLASK_SECRET_KEY 必设；钉钉 AppKey/Secret 可选（一旦设置会启用登录门禁，需同时设 APP_BASE_URL 并在钉钉后台加回调白名单）。
- 验证：test_client import app 后 GET /api/dashboard → 200，WSGI 对象 app.app 为 Flask 实例，gunicorn `app:app` 可加载。
- 部署说明写入 `Zeabur部署指南.md`。无法远程代操作 Zeabur（无连接器），交付配置 + 手册。

## Zeabur 改用 CLI 直传（用户 github.com 打不开）
- 原方案走 GitHub 仓库 push → 因 github.com 不可访问作废。
- 新主线：Zeabur CLI 本地直传，全程不依赖 GitHub。
  - 注册 Zeabur 用**邮箱/Google**（别选 GitHub）。
  - 登录 `npx zeabur@latest auth login` → 浏览器开 Zeabur 网站邮箱登录 → Confirm 回传 token，不经过 github.com。
  - 部署 `npx zeabur@latest deploy`（项目目录内，自动识别 Python + zbpack.json）。
- 新增 `.zeaburignore`：屏蔽 `*.db`、`__pycache__`、`.workbuddy/`、`启动.bat`/各 .sh、文档 md 等，避免上传本地库、密钥、缓存。
- 指南重写为「不依赖 GitHub」版，GitHub 方式降级为可选补充。
- 前提提醒：zeabur.com 须能开；首次建项目需验证账号（手机/余额/信用卡）。
- 交付 `zeabur-deploy.bat`（调用 WorkBuddy node 绝对路径 npx.cmd）。**关键**：bat 内必须把 NODE_DIR 加到 PATH（`set "PATH=%NODE_DIR%;%PATH%"`），否则 npx.cmd 内部调 `node` 报“不是内部或外部命令”。原因：仅 WorkBuddy 工具 shell 的 PATH 含该 node，用户独立 cmd 窗口的 PATH 不含，直接 `npx` 也不可用，须走 bat。
- 用户实测双击 bat：auth login 成功；deploy 提示 `No projects found. Would you like to create one now? (Y/n)`，需输入 Y 回车创建首个项目，再输项目名/选区域(Hong Kong)/环境(回车默认)。勿按 Ctrl+C 否则 `ERROR interrupt`。bat 结束文案改中性，不再误导为成功。
- 实测 CLI 交互创建项目报 `Failed to create project: invalid region code`（CLI 传了服务端不认的 region code，已知坑，与用户操作无关）。绕过：网页 zeabur.com 手动 New Project 选 Hong Kong 建空项目，再 CLI deploy 选已有项目。已写入指南常见问题。

## 切换为 Koyeb 部署（Docker Hub + Koyeb）— 弃用 Zeabur

  - 本地验证：import app OK，GET /api/dashboard → 200，DATA_DIR 默认仍指向项目 data/。
- 指南：`Koyeb部署指南.md`（路线A 镜像推送 + Koyeb 控制台部署；路线B Koyeb CLI 本地目录云端构建免Docker；环境变量表；Volume 挂 /data；FLASK_SECRET_KEY；钉钉可选）。
- 关键提醒：Koyeb 实例磁盘临时，必须挂 Volume 到 /data 持久化 SQLite；免费额度若不支持 Volume 则数据会丢，可用 /download-project 导出备份。
