## 追加修复：启动.bat 编码/目录/PATH 问题（用户双击报错满屏乱码 + 弹出"打开方式"）
现象：
1. `启动.bat` 运行后中文全变乱码，每条 `echo` 中文都被当成命令 -> "不是内部或外部命令"。
2. 从非脚本目录运行时出现"系统找不到指定的驱动器"。
3. 最后弹出"你要如何打开这个文件？"让选记事本/Microsoft Store（说明没找到 Python，命令变成了裸 `app.py`）。
根因：
1. 文件是 UTF-8 无 BOM，中文 Windows 的 cmd 默认按 GBK 读取 -> 中文全乱。
2. 脚本没有先切到自身目录。
3. 系统 PATH 里没有 `python`，`python app.py` 退化成 `app.py`，Windows 只能弹打开方式。
修复：
- 重写为 **GBK/ANSI（CP936）** 编码，与中文 Windows cmd 默认代码页一致，无需 `chcp` 中文即可正常显示。
- 第二行加 `cd /d "%~dp0"`，保证永远在脚本自身目录运行。
- Python 探测改为优先查找确定存在的 WorkBuddy 托管解释器：
  `C:\Users\123\.workbuddy\binaries\python\versions\3.13.12\python.exe`；
  找不到再依次检查 `C:\Python313/312/311/310\python.exe`；
  最后才用 PATH 中的 `python`/`python3`/`py`。
- 依赖安装用 `%PY% -m pip install -r requirements.txt -q`，启动用 `%PY% app.py`，避免 PATH 问题。
- 校验：od 确认文件头为 `@echo off`（无 BOM），GBK 读取中文"客户管理工作空间"完整保留。
- 顺手把 deploy.sh 的 Dockerfile 里 `folium dingtalk-sdk` 也去掉（与 requirements 保持一致）。

## 追加修复：app.py 调试模式稳定性 + 启动窗口说明
- 用户反馈"页面过一会儿就失效"。根因：命令行窗口（Flask 进程）被关闭即服务器停止；且 `app.run(debug=True)` 开自动重载子进程，本地长期跑易自崩。
- 修复：app.py 末尾改为 `app.run(host="0.0.0.0", port=port, debug=False, use_reloader=False)`。
- 已向用户说明：黑窗口即服务器本体，必须保持运行（最小化即可，勿关闭）；关窗口=停服务=页面失效。
- 用户选择"暂时不动"，暂不加 pythonw 无窗口后台版（如需再补 `启动-后台.bat` + `停止后台.bat`）。

## 2026-07-10 修复：业务页"新增业务"按钮点不开
- 现象：/business 页点"新增业务"无反应（表格也卡加载）。
- 根因：business.html deleteBusiness 的 onclick 转义写错——`.replace(/'/g, '\\'')` 里 `'\\''`
  是未终止字符串，整个内联 <script> 报 SyntaxError，导致 openBusinessModal 等全部函数未定义。
- 修复：改为 `.replace(/'/g, "\\'")`（双引号包裹替换串）。node --check 抽取内联 JS 验证 JS_SYNTAX_OK。
- 教训：模板字面量里往 onclick 拼字符串时，单引号转义务必用双引号包裹替换串，避免引号打架。
